# M1: 工程搭建

## 目标

搭建 monorepo 项目基础结构，完成依赖管理和构建配置。

## 需要 vendor 至本地的包

| 包名 | 用途 | vendor 原因 |
| --- | --- | --- |
| cordis | 核心 IoC 框架 | 需要深度定制和版本控制 |
| schemastery | Schema 校验 | cordis 依赖，需保持版本一致 |
| cosmokit | 工具函数集 | cordis 依赖，需保持版本一致 |
| @cordisjs/plugin-loader | 插件加载器 | 需要自定义加载逻辑 |
| react | UI 渲染框架 | 统一版本，避免插件间版本冲突 |
| react-dom | DOM 渲染 | 与 react 版本绑定，统一管理 |

## 目录结构

```
cordis-tavern/
├── pnpm-workspace.yaml
├── package.json
├── tsconfig.base.json
├── vendor/
│   ├── cordis/
│   ├── plugin-loader/
│   ├── schemastery/
│   ├── cosmokit/
│   ├── react/
│   └── react-dom/
├── bootstrap/
│   └── index.ts
└── .env
```

## 配置文件内容

### pnpm-workspace.yaml

定义 workspace 只包含 `vendor/*`。仓库内**不含插件包**——插件是 npm 包，由 pnpm 安装到 `$CT_HOME/node_modules/`。

### package.json（根）

定义项目名称、构建脚本和 TypeScript 依赖。

### tsconfig.base.json

定义 TypeScript 编译选项：target ES2020、ESNext 模块、bundler 解析策略、严格模式。

## 验收标准

- [x] `pnpm install` 执行成功
- [x] vendor 目录下六个依赖包存在
- [x] TypeScript 配置可正常编译

### 实施记录

实际交付**八个** vendor 包（原计划六个），额外 vendor 了 `@cordisjs/plugin-include` 与 `node-addon-require-builtin`，以补齐 `@cordisjs/plugin-loader` 的 peer 依赖缺口。

验收方式（对应上面三项）：

```bash
pnpm install        # 验收 1
pnpm vendor:check   # 验收 2：校验八个目录存在，且各自 package.json 的 name 等于期望的上游包名
pnpm typecheck      # 验收 3：tsc --noEmit，test/ 下真实 import 八个包
```

三项均已通过。实施期的额外发现与决策记录在 `cordis-tavern/docs/M1-工程搭建-设计.md`，其中较重要的两条：

- **pnpm 11 不再读 `package.json` 的 `pnpm.overrides`**，workspace 级配置必须写在 `pnpm-workspace.yaml`。
- **vendor 包需清洗 manifest**：上游发布的 `package.json` 会带 `devDependencies`（如 cosmokit 带 esbuild/mocha），而 vendor 目录是 workspace 成员，pnpm 会为其安装 devDependencies，导致 `pnpm install` 直接硬失败。
