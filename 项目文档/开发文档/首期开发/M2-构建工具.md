# M2: 构建工具

## 目标

实现基于 esbuild 的自定义构建工具，统一管理插件构建流程。

详细设计参见 → [[项目文档/项目文档/cordis-tavern项目设计/自定义构建工具|自定义构建工具]]

## 目录结构

```
cordis-tavern/
├── scripts/
│   ├── build.mjs
│   └── dev.mjs
├── build.config.ts
└── ...
```

> 仓库内**不含插件包**（插件是 npm 包，由 pnpm 装进 `$CT_HOME/node_modules/`），
> 因此构建工具支持用参数把扫描根指向仓库外的插件开发目录。

## 构建工具设计

### build.config.ts

配置预设外部依赖（cordis、schemastery、cosmokit、@cordisjs/plugin-loader、react、react-dom），配置全局变量、tree shaking 和 source map 选项。

### scripts/build.mjs

核心逻辑：
1. 扫描插件根目录下的所有插件（判据：含 `package.json`、含 `ct` 字段、`exports["."].source` 指向的入口存在）
2. 读取各插件的 `package.json` 中的 `exports["."].source` 字段获取源码入口
3. 合并预设外部依赖与 `ct.external`
4. 调用 esbuild 进行打包
5. 输出到各插件的 `dist/` 目录

### scripts/dev.mjs

在构建基础上增加 watch 能力，用 esbuild 自带的 `context()` + `watch()` 实现增量重建。

## 验收标准

- [ ] `pnpm build` 执行成功，所有插件产物输出到 `dist/`
- [ ] 能够正确识别插件入口并打包
- [ ] vendor 中的依赖（cordis、schemastery 等）不被打入产物
- [ ] 插件级外部依赖（`ct.external`）不被打入产物
- [ ] 开发模式下文件变动可自动增量重建
