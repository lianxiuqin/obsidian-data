# 骨架开发

本文档详细说明首期开发各里程碑的具体实现内容。

---

## M1: 工程搭建

### 目标

搭建 monorepo 项目基础结构，完成依赖管理和构建配置。

### 需要 vendor 至本地的包

| 包名 | 用途 | vendor 原因 |
| --- | --- | --- |
| cordis | 核心 IoC 框架 | 需要深度定制和版本控制 |
| schemastery | Schema 校验 | cordis 依赖，需保持版本一致 |
| cosmokit | 工具函数集 | cordis 依赖，需保持版本一致 |
| @cordisjs/plugin-loader | 插件加载器 | 需要自定义加载逻辑 |

### 目录结构

```
cordis-tavern/
├── pnpm-workspace.yaml
├── package.json
├── tsconfig.base.json
├── vendor/
│   ├── cordis/
│   ├── plugin-loader/
│   ├── schemastery/
│   └── cosmokit/
├── bootstrap/
│   └── index.ts
└── .env
```

### 配置文件内容

#### pnpm-workspace.yaml

定义 workspace 包含 `vendor/*` 和 `packages/*` 两个目录。

#### package.json（根）

定义项目名称、构建脚本和 TypeScript 依赖。

#### tsconfig.base.json

定义 TypeScript 编译选项：target ES2020、ESNext 模块、bundler 解析策略、严格模式。

### 验收标准

- [ ] `pnpm install` 执行成功
- [ ] vendor 目录下四个依赖包存在
- [ ] TypeScript 配置可正常编译

## M2: 构建工具

### 目标

实现基于 esbuild 的自定义构建工具，统一管理插件构建流程。

### 目录结构

```
cordis-tavern/
├── scripts/
│   ├── build.js
│   └── dev.js
├── build.config.ts
└── ...
```

### 构建工具设计

#### build.config.ts

配置预设外部依赖（cordis、schemastery、cosmokit、@cordisjs/plugin-loader），配置全局变量、tree shaking 和 source map 选项。

#### scripts/build.js

核心逻辑：
1. 扫描 `packages/` 目录下的所有插件
2. 读取各插件的 `package.json` 中的 `ct.bundle` 字段获取入口
3. 调用 esbuild 进行打包
4. 输出到各插件的 `dist/` 目录

### 验收标准

- [ ] `pnpm build` 执行成功
- [ ] 能够正确识别插件入口并打包
- [ ] vendor 中的依赖不被打入产物

## M3: 核心基建

### 目标

实现启动层（IoC 容器）和插件注册表/环境表，完成插件生命周期管理。

### 目录结构

```
cordis-tavern/
├── packages/
│   └── core/
│       ├── package.json
│       ├── src/
│       │   ├── index.ts
│       │   ├── context.ts
│       │   ├── registry.ts
│       │   └── lifecycle.ts
│       └── tsconfig.json
└── ...
```

### 核心模块设计

#### context.ts

基于 cordis 的 Context 机制，提供插件运行时上下文，包括插件元数据、配置访问、事件总线和子上下文创建能力。

#### registry.ts

插件注册表，管理所有已注册插件的元数据和依赖关系，提供注册、获取、拓扑排序计算加载顺序、获取环境表等功能。

#### lifecycle.ts

插件生命周期管理，定义插件状态（Pending、Loading、Active、Disposed），提供加载、激活、卸载和状态查询功能。

### 验收标准

- [ ] 应用可正常启动
- [ ] 插件可注册到注册表
- [ ] 插件可按依赖顺序加载

## M4: 插件契约

### 目标

实现 `package.json` 中 `ct` 字段的解析，完成插件声明发现机制。

### 目录结构

```
cordis-tavern/
├── packages/
│   └── contract/
│       ├── package.json
│       ├── src/
│       │   ├── index.ts
│       │   ├── parser.ts
│       │   ├── types.ts
│       │   └── validators/
│       │       ├── bundle.ts
│       │       ├── client.ts
│       │       └── commands.ts
│       └── tsconfig.json
└── ...
```

### 声明格式定义

#### ct.bundle

声明插件的 bundle 配置路径。

#### ct.client

声明插件的前端结构，包括 platform（平台）、inject（依赖插件）、immediately（是否预加载）、external（外部包依赖）。

#### ct.commands

声明插件提供的命令，包括 command（命令名）、path（入口路径）、explain（说明）、subcommands（子命令组）。

### 解析器设计

#### parser.ts

提供声明解析器，支持解析单个插件声明、批量解析和声明格式校验。定义 PluginContract 接口，包含 name、bundle、client、commands 字段。

### 验收标准

- [ ] 可正确解析 `ct.bundle` 字段
- [ ] 可正确解析 `ct.client` 字段
- [ ] 可正确解析 `ct.commands` 字段
- [ ] 可发现所有已声明的插件

## M6: 基础插件 - client-web

### 目标

实现 client-web 插件，负责前端声明发现、`window.boot` 排序和惰性加载控制。

### 目录结构

```
cordis-tavern/
├── packages/
│   └── plugins/
│       └── client-web/
│           ├── package.json
│           ├── src/
│           │   ├── index.ts
│           │   ├── discovery.ts
│           │   ├── boot.ts
│           │   └── lazy.ts
│           └── tsconfig.json
└── ...
```

### 核心功能

#### discovery.ts

前端声明发现模块，扫描所有插件的 `ct.client` 声明，构建前端插件列表，按依赖关系排序。

#### boot.ts

`window.boot` 管理模块，控制插件加载顺序，支持立即加载和延迟加载两种模式。

#### lazy.ts

惰性加载控制模块，支持注册惰性加载模块、按需加载和预加载功能。

### 验收标准

- [ ] 可发现所有前端插件声明
- [ ] 可按依赖关系正确排序
- [ ] 惰性加载机制正常工作

## M8: 基础插件 - logRouter

### 目标

实现 logRouter 插件，提供日志分级与路由输出。

### 目录结构

```
cordis-tavern/
├── packages/
│   └── plugins/
│       └── logRouter/
│           ├── package.json
│           ├── src/
│           │   ├── index.ts
│           │   ├── logger.ts
│           │   ├── router.ts
│           │   └── transports/
│           │       ├── console.ts
│           │       └── file.ts
│           └── tsconfig.json
└── ...
```

### 核心功能

#### logger.ts

日志接口模块，定义日志级别（Debug、Info、Warn、Error）和 Logger 接口，提供 debug、info、warn、error 方法和级别设置功能。

#### router.ts

日志路由模块，提供注册/移除输出目标、路由日志到匹配的输出目标功能。定义 LogTransport 接口（name、minLevel、maxLevel、write）和 LogEntry 接口（level、message、timestamp、source、data）。

#### transports/

输出目标实现：
- console.ts：控制台输出，将日志格式化后输出到控制台
- file.ts：文件输出，将日志写入文件

### 验收标准

- [ ] 日志可按级别输出
- [ ] 支持控制台输出
- [ ] 支持文件输出
- [ ] 可动态添加/移除输出目标
