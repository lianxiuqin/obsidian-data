## 一、一句话现状

仓库（`cordis-tavern`）交付的是**内核侧**：启动层 + 插件表装配 + CLI + 构建工具 + vendor 本地化 + 测试。

仓库**刻意不含任何插件包**（`pnpm-workspace.yaml` 的 `packages` 只匹配 `vendor/*`）。
四个基础插件的实现**不在本仓库**：`@cordis-tavern/ct-host-web`（`0.0.1-alpha.3`）已在插件仓库落地最简版，其余三个未开工。

## 二、包身份与工程基线

| 项 | 值 |
|---|---|
| 包名 | `@cordis-tavern/cordis-tavern` |
| 版本 | `0.0.3-rc`（已发布到 registry，`latest`） |
| 入口 | `main: dist/index.js`（启动层）、`bin: ct → dist/cli/index.js`（CLI） |
| 模块制式 | `type: module`（ESM） |
| Node | `>= 22.18` —— 源码目录由 **Node 原生类型剥离**直接执行，因此只能用**可擦除语法**、相对导入必须带 `.ts` 扩展名 |
| 包管理器 | `pnpm@12.4.1`（`packageManager` 固定；所有 pnpm 配置写在 `pnpm-workspace.yaml`，pnpm 11+ 不再读 `package.json` 的 `pnpm` 字段） |
| 发布物 | `files: ["dist/"]`，由 `pnpm build:dist` 产出 |
| 运行时依赖 | `dependencies` **只有 `js-yaml`**；5 个内核库在 `devDependencies` —— 内核由 `ct init` 装配进 `$CT_HOME`，主包不持有 |
| TypeScript 基线 | `target/lib: ES2020`、`module: ESNext`、`moduleResolution: bundler`、`strict`、`erasableSyntaxOnly`、`verbatimModuleSyntax`、`isolatedModules`、`noEmit`、`skipLibCheck`、`types: ["node"]` |

## 五、验证方式

| 命令 | 验证内容 | 现状 |
|---|---|---|
| `pnpm install` | 依赖安装（esbuild 的 postinstall 由 `allowBuilds` 放行） | 通过 |
| `pnpm vendor:check` | 五个 vendor 目录存在、各自 `name` 等于期望的发布名、补丁与说明符改写已生效（离线，不联网） | 通过 |
| `pnpm typecheck` | `tsc --noEmit`；`test/vendor.test.ts` 真实 import 五个 vendor 包**与**一个后端库（`node-addon-require-builtin`），同时证明 tsconfig 可用、指向本地副本、且后端库能经 link 农场解析 | 通过 |
| `pnpm test:single-instance` | 运行时单实例回归（14 项）：cosmokit 的 `Binary`/`Time`/`clone` 在 `require` 与 `import` 下同一身份、schemastery 同份且校验为同步值、4 个后端库双制式均可加载、**前端库静态表已并入 external 且不进 vendor**、**主包 `dependencies` 不含内核** | 通过 |
| `pnpm test:cli` | `node --test test/cli.test.mjs`：仓库根 / CT_HOME / CT_PROFILE / 注册表 / `ct init` 脚手架 / pnpm 守卫 / **内核版本表与装配计划** | 通过（52 用例；本机 Windows 且仓库根无 `.env` 时 51 通过 / 1 skip） |
| `pnpm test:plugin` | `test/plugin.test.mjs`：契约解析、`profileDir` 守卫、`ct.profile` 读写、参数解析、命令表重放、add/remove/update 的原子性与动词判据 | 通过 |
| `pnpm test:startup` | `node --test test/startup.test.mjs`（**59 项**）：`resolveHome` / `readProfileName`、`readInsertRows`、`readPatch`、`assemble`、跨层一致性护栏、`start()` 端到端与异步就绪、**内核根锚点**与**跨树单实例** | 通过 |
| `pnpm build` | 插件构建。**仓库内无插件**，因此打印「没有在 packages 下找到插件」并 exit 0 | 通过（空跑） |
| `pnpm build:dist` | 发布构建 → `dist/`（含命令注册表改写与自检） | 通过 |
| `pnpm dev` | watch 插件（仓库内无插件时空跑退出） | 可用 |
| 跨盘消费者冒烟（手工复核） | `pnpm pack` → 装进 `%TEMP%` 的消费者项目（**C:，而仓库在 D:**）→ `ct init`（装配 5 个内核包）→ `ct update`（幂等）→ `start()`（从 `$CT_HOME` 装载内核）。三步全部通过 | 通过 |

> ⚠️ 没有聚合的 `pnpm test`：五个测试入口需分别执行。
