Cordis 项目架构开发方案 v2.0（高解耦·缓存友好型）

一、 项目核心基建层（非插件，项目内核）

此层不依赖任何业务插件，负责应用的生命周期与基础环境。

模块 职责描述 关键设计
0. IoC 容器（启动层） 应用的唯一入口，负责扫描、实例化、依赖注入（DI）所有插件。 基于 Reflect Metadata 实现自动装配，禁止插件间 new 实例化。

事件总线（Event Bus） 模块间通信的唯一介质。 仅允许 Pub/Sub，禁止直接引用其他插件的 API（除非通过 Interface）。

配置中心（Config Center） 统一管理 .env、CLI 参数、用户配置。 支持运行时 watch 更新，所有插件通过 ctx.config 拉取。

自定义构建工具（Build Tool） 基于 Esbuild/Rollup 封装，防止重复打包。 开启 sideEffects: false，支持 Tree Shaking。

二、 插件核心契约层（接口定义，无实现）

此层仅定义 interface 和 type，供其他插件实现或调用，确保逻辑解耦。

4. 插件注册表（替代原 7 & 8） 统一管理所有插件的元数据、版本、依赖关系。 内置拓扑排序（Topological Sort） 自动计算加载顺序，无需人工维护。

插件名称 职责描述 关键设计
7. 存储驱动实现（原 14 拆解） 提供 JSON / SQLite / IndexedDB 的具体驱动。 仅需实现 IStorageDriver 接口，由配置中心决定加载哪个。

四、 ⭐ 核心业务域：聊天与 Prompt 系统（重点修改区）

这是本次修改的重中之重，完全采用 “手动蓝图 + 注册池” 模式以保缓存命中率。

插件名称 职责描述（修改后） 关键设计（高解耦核心）
12. Prompt 蓝图管理器（重构） 用户/开发者手动编写 Prompt 结构的模板文件。 顺序硬编码：模板内使用 {{key}} 占位符。 不进行任何运行时排序，仅做纯文本字符串替换。
13. 蓝图变量校验器（新增） 发送请求前的静态检查（Lint）。 检查蓝图中的变量 {{key}} 是否在 「Prompt 注册池」 中声明。未声明的变量高亮警告，但不自动注入，防止污染缓存。
14. 世界书插件（修改） 存储世界背景信息。 变为被动 KV 池：仅通过 world_book.get('key') 供蓝图调用。 禁止自动激活或自动插入，完全由用户决定是否在蓝图中写入 {{world_book.某标签}}。
15. 蓝图版本与哈希缓存（新增） 管理用户保存的蓝图版本。 对编译后的最终 Prompt 计算哈希（Hash），作为 KV-Cache 的 Key。 用户不改蓝图，哈希永远不变，最大化复用云端 KV Cache。
16. LLM 传输适配器（原 9 修改） 调用大模型接口的兼容层。 支持 OpenAI / Anthropic / 国内模型格式转换。
17. Chat 后端调度器（原 11 修改） 处理完整请求链路。 快照模式：若本次蓝图哈希与上次相同，剥离 System Prompt，仅传输 User Query 增量变体。
18. Chat 消息显示前端（原 10） 读取流式数据并渲染。 独立接入 流式渲染引擎（SSE/WS），与主逻辑线程分离。
19. 多对话管理（原 15） 创建、切换、删除对话会话。 每次切换时，加载对应会话的独立蓝图配置，互不干扰。
