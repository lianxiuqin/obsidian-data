# 插件概念总览

状态：🟡 初步设计（四个插件中只有 host 落地了最简版，其余三个未开工）

> **插件不在本仓库**：它们是独立 npm 包，由 pnpm 装进 `$CT_HOME` 的 node_modules。
> 每个插件自己的设计在自己的文件夹里（见下表）；本页只写共性的东西与索引。

## 插件是什么

- 一个**模块化的 npm 包**：身份与入口用 npm 标准字段声明，npm 表达不了的语义用 `ct` 扩展字段 —— `ct` 是**扩展，不是替代**。
- 它的产物**不在 cordis-tavern 仓库内**：该仓库的 `pnpm-workspace.yaml` 的 `packages` 只匹配 `vendor/*`。
- 包名正典：**`@cordis-tavern/ct-*`**（详见 [[项目文档/项目设计文档/插件设计/插件契约层|插件契约层]] 的「包命名」）。

## 与内核的对接约定（四个插件通用）

| 约定 | 要求 |
|---|---|
| 装载 | 包名写进环境级 `ct.profile`；包目录须位于 `$CT_HOME/profile/<env>/node_modules/`（`ct plugin add -p <env>`）或 `$CT_HOME/node_modules/`（`ct plugin add -g`） |
| bundle | `package.json` 的 `ct.bundle.path` 指向包内 `cordis.patch.yml`，其 `insert[]` 声明服务 id 与要装载的包名 |
| 服务 | 通过 `ctx.provide()` / `inject` 暴露与声明能力；**加载顺序由依赖关系决定**，与 `ct.profile` 顺序无关 |
| 配置 | 插件自带 config 写在 insert 行的 `config`；用户可用两层 `cordis.patch.yml` 覆盖，**整行替换**（见 [[项目文档/项目设计文档/内核设计/启动层|启动层]]） |
| 若提供 CLI 命令 | `ct.commands[].path` 必须指向**已构建的** `.js` / `.mjs`（`.ts` 在 node_modules 下加载不了） |

> 契约细节（字段、校验规则、包命名）只写在 [[项目文档/项目设计文档/插件设计/插件契约层|插件契约层]]；
> 未交付与未定案项在 [[项目文档/开发文档/待办|待办]]。
