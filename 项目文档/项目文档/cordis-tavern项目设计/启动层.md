# 启动层

## 概述

启动层是 cordis-tavern 的应用入口，负责完成从"读取配置"到"插件就绪"的全部流程。它不实现任何业务逻辑，只做三件事：

1. **发现插件**：按环境级清单（`$CT_HOME/profile/web/package.json` 的 `ct.profile`）读取插件名，从 `$CT_HOME/node_modules/` 定位插件包
2. **合并配置**：将插件声明、环境配置、用户配置按优先级合并
3. **交出控制权**：将最终的插件表交给 `@cordisjs/plugin-loader`，由 Cordis 完成依赖驱动的加载

入口文件为 `bootstrap/index.ts`。它对外暴露函数，供其他插件通过路径调用。

---

## 启动流程

```
┌──────────────────────────────────────────────────────────┐
│  1. 读取 .env → 获取 $CT_HOME                             │
├──────────────────────────────────────────────────────────┤
│  2. 读取 $CT_HOME/profile/web/package.json → 获取 ct.profile │
│     （插件名称列表）                                        │
├──────────────────────────────────────────────────────────┤
│  3. 遍历 ct.profile，从 $CT_HOME/node_modules/ 中读取每个插件包 │
│     → 读取插件的 cordis.patch.yml（insert 声明）             │
│     → 生成初始插件表单（记录 id 与 name 的映射）              │
├──────────────────────────────────────────────────────────┤
│  4. 插件覆盖（后来者居上）                                   │
│     → 若后加载的插件 id 与已有插件 id 重合，覆盖前者           │
├──────────────────────────────────────────────────────────┤
│  5. 配置覆盖（优先级合并）                                   │
│     → 用户级 cordis.patch.yml                              │
│     → 环境级 cordis.patch.yml                              │
│     → 插件 Config schema（默认值）                          │
├──────────────────────────────────────────────────────────┤
│  6. 生成最终插件表（内存中，不落盘）                           │
│     → 传递给 @cordisjs/plugin-loader                       │
│     → plugin-loader 根据 inject 依赖关系自动排序并加载        │
└──────────────────────────────────────────────────────────┘
```

## 插件发现

### 插件列表来源

从环境级 `package.json`（`$CT_HOME/profile/web/package.json`）的 `ct.profile` 数组读取插件名称列表。

```json
{
  "ct": {
    "profile": [
      "ct-plugin-host",
      "ct-plugin-client-web",
      "ct-plugin-frontend-static",
      "ct-plugin-log-router"
    ]
  }
}
```

### 插件包读取

依据 `ct.profile` 中的名称，从 `$CT_HOME/node_modules/` 中读取对应的插件包。每个插件包内包含：

- `package.json`：插件元数据，其中 `ct.bundle.path` 指向该插件的 `cordis.patch.yml`
- `cordis.patch.yml`：插件的 insert 声明（与用户/环境级的 `cordis.patch.yml` 格式不同）

---

## 插件覆盖机制（insert）

### 插件级 cordis.patch.yml

每个插件的 `cordis.patch.yml` 存储的是 **insert 声明**，用于声明插件提供的服务 id 与名称的映射关系。

```yaml
# 插件 ct-plugin-chat 的 cordis.patch.yml
- insert:
    - id: chat
      name: chat-plugin
```

**与用户/环境级 `cordis.patch.yml` 的区别**：两者的格式**天然不同**——插件级是 insert 声明（服务 id → name 映射），用户级/环境级是配置覆盖（`id` + `config`）。

| 文件 | 位置 | 内容 | 用途 |
|---|---|---|---|
| 插件级 | `$CT_HOME/node_modules/<plugin>/cordis.patch.yml` | insert 声明（id → name 映射） | 声明插件提供的服务 |
| 用户级 | `$CT_HOME/cordis.patch.yml` | 配置覆盖（`id` + `config`） | 用户自定义配置 |
| 环境级 | `$CT_HOME/profile/web/cordis.patch.yml` | 配置覆盖（`id` + `config`） | 环境特定配置 |

用户级 / 环境级示例：

```yaml
- id: host
  config:
    vmTimeoutMs: 10000
```

### 后来者居上原则

当启动层遍历插件列表时，若后加载的插件声明的 `id` 与已有插件的 `id` 重合，后者的 insert 会**自动覆盖**前者。

```
插件 A: insert: [{ id: "chat", name: "chat-v1" }]
插件 B: insert: [{ id: "chat", name: "chat-v2" }]

→ 最终结果: { id: "chat", name: "chat-v2" }  （B 覆盖 A）
```

这使得用户可以通过安装同类型的插件来替换默认实现，无需手动卸载。

## 配置覆盖机制

启动函数被调用后，按以下顺序合并配置，优先级从低到高：

```
插件 Config schema（默认值）
  ↑ 被环境级配置覆盖
  ↑ 被用户级配置覆盖
```

即最终优先级：**用户级 > 环境级 > 插件默认值**

| 层级 | 文件路径 | 说明 |
|---|---|---|
| 插件默认值 | 插件代码内的 `Config` 定义 | 插件自带的默认配置 |
| 环境级 | `$CT_HOME/profile/web/cordis.patch.yml` | 当前环境的配置覆盖 |
| 用户级 | `$CT_HOME/cordis.patch.yml` | 用户个人的配置覆盖 |

Cordis 通过 `ctx.intercept(name, config)` 机制实现配置的层级合并，祖先条目优先。

---

## 输出：插件表

启动层最终在内存中生成一张**插件表**，包含：

- 插件 id（insert 声明中的 id）
- 插件 name（insert 声明中的 name）
- 合并后的配置（经过三层覆盖）

该表**不进行本地留存**，直接传递给 `@cordisjs/plugin-loader`。

---

## 与 plugin-loader 的衔接

`@cordisjs/plugin-loader` 接收启动层产出的插件表后：

1. 根据每个插件的 `inject` 声明，计算依赖关系
2. 通过拓扑排序确定加载顺序
3. 依次调用 `ctx.plugin()` 加载插件
4. 由 Cordis 内核管理 Fiber 生命周期（PENDING → LOADING → ACTIVE）

加载顺序由**依赖关系**决定，而非文件顺序。若插件 A 依赖插件 B，则 B 一定先于 A 加载。

## 目录结构

```
cordis-tavern/
├── bootstrap/
│   └── index.ts          # 启动层入口，对外暴露函数供插件调用
├── vendor/               # 本地化的依赖（目录名可短于包名）
│   ├── cordis/
│   ├── schemastery/
│   ├── cosmokit/
│   ├── plugin-loader/    # @cordisjs/plugin-loader
│   ├── plugin-include/   # @cordisjs/plugin-include
│   ├── require-builtin/  # node-addon-require-builtin
│   ├── react/
│   └── react-dom/
└── $CT_HOME/             # 默认 ./ct，由 .env 的 CT_HOME 指定
    ├── profile/
    │   └── web/
    │       ├── package.json       # 包含 ct.profile 插件列表
    │       ├── cordis.patch.yml   # 环境级配置覆盖
    │       └── commands.yml       # 环境级命令注册（profile 原生自带，由 CLI 管理）
    ├── node_modules/              # 已安装的插件包
    ├── package.json               # 用户级依赖清单
    └── cordis.patch.yml           # 用户级配置覆盖
```
