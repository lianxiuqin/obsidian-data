# 插件契约层

## 核心声明

**插件是一个模块化的 npm 包**。开发者用 npm 标准字段声明包的身份与入口，再通过约定字段 `ct` 声明 npm 表达不了的语义——`ct` 是 npm 声明的**扩展，不是替代**。

### 标准 npm 字段（负责"是什么、入口在哪"）

| 字段 | 作用 |
|---|---|
| `name` | 包名。与 insert 声明的 `name` 保持一致（见[[项目文档/项目文档/cordis-tavern项目设计/启动层\|启动层]]） |
| `version` | 版本 |
| `type` | **必须为 `"module"`**——产物是 ESM，缺此字段会被 Node 判为 CJS |
| `exports["."].source` | **源码入口**（构建工具的输入） |
| `exports["."].types` | 类型入口 |
| `exports["."].import` | 运行时入口（构建产物） |

### 扩展字段（`ct`）

`ct` 承载 npm 无法表达的语义：

```json
{
  "ct": {
    "entry": "./dist/index.js",
    "bundle": {
      "path": "./cordis.patch.yml"
    },
    "external": ["lodash-es"]
  }
}
```

| 字段 | 含义 |
|---|---|
| `ct.entry` | **编译后的入口文件**（npm 无此概念——`exports` 描述的是发布后的形态，不区分源码与产物） |
| `ct.bundle.path` | 指向该插件的 `cordis.patch.yml` |
| `ct.external` | 构建期外部依赖，作用于该插件的**全部**产物 |

## 前端 / 前后端插件声明

通过 `ct.client` 声明。**后端的 `ct` 由启动层解析，前端的 `ct.client` 由插件解析**；由于涉及执行操作，因此与 Cordis 无关。

```json
{
  "ct": {
    "client": {
      "platform": "web",
      "inject": ["ct-plugin-log-router"],
      "immediately": true
    }
  }
}
```

- `platform`：声明该插件前端结构的**目标平台**（当前为 `web`，未来可扩展 `desktop` 等）。
  **存在 `ct.client` 即表示该插件包含前端结构**——不需要另设开关字段。
- `inject`：声明该插件的前端结构依赖哪些插件（用于前端加载排序，**不参与后端加载排序**——后端的加载顺序由 cordis 的 `inject` 依赖声明决定）。
- `immediately`：声明该插件是预加载，还是仅注册工厂函数以进行惰性加载。

> **外部依赖不在 `ct.client` 下**：构建期的外部依赖统一由 `ct.external` 声明（见上文「扩展字段」），因为它作用于该插件的**全部**产物，而非仅前端产物。

## 命令声明

通过 `ct.commands` 字段声明。

```json
{
  "ct": {
    "commands": [
      {
        "command": "build",
        "path": "./src/commands/build.ts",
        "explain": "构建当前插件",
        "subcommands": [
          {
            "subcommand": "all",
            "explain": "构建全部插件"
          }
        ]
      },
      {
        "command": "test",
        "path": "./src/commands/test.ts",
        "explain": "运行测试",
        "subcommands": []
      }
    ]
  }
}
```

- `commands`：声明多个命令。
- `command`：声明一个命令名。
- `path`：**命令入口文件**（源码，构建输入）。
- `explain`：说明命令功能。
- `subcommands`：声明子命令组。
- `subcommand`：声明单个子命令。

> **子命令没有 `path`**：CLI 采用 git 式的**调度**模型——主 CLI 文件存一张「命令名 → 处理函数」的表，子命令只声明名字与说明，由主文件分派。

## 环境级插件清单

环境级 `package.json`（`$CT_HOME/profile/web/package.json`）用 `ct.profile` 声明**需要加载哪些插件**：

```json
{
  "ct": {
    "profile": [
      "ct-plugin-host",
      "ct-plugin-client-web"
    ]
  }
}
```

它决定**加载哪些**插件；**加载顺序**由 `inject` 依赖关系决定，不由本清单顺序决定。详见[[项目文档/项目文档/cordis-tavern项目设计/启动层|启动层]]。

## `package.json` 声明汇总

一个完整的插件 `package.json`：

```json
{
  "name": "ct-plugin-host",
  "version": "0.1.0",
  "type": "module",
  "exports": {
    ".": {
      "source": "./src/index.ts",
      "types": "./src/index.ts",
      "import": "./dist/index.js"
    }
  },
  "ct": {
    "entry": "./dist/index.js",
    "bundle": {
      "path": "./cordis.patch.yml"
    },
    "external": ["lodash-es"],
    "client": {
      "platform": "web",
      "inject": ["ct-plugin-log-router"],
      "immediately": true
    },
    "commands": [
      {
        "command": "build",
        "path": "./src/commands/build.ts",
        "explain": "构建当前插件",
        "subcommands": [
          {
            "subcommand": "all",
            "explain": "构建全部插件"
          }
        ]
      }
    ]
  }
}
```

> `name` / `version` / `type` / `exports` 均为**标准 npm 字段**；`ct` 块是**扩展**，二者并存。
> `ct.client` 整块可省略（纯后端插件无需前端声明）；`ct.commands` 可省略（无 CLI 命令的插件）。
> 环境级 `package.json` 只用 `ct.profile`，不用上述其他字段。
