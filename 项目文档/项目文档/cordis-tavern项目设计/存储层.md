# 存储层

## 设计原则

Cordis 的设计哲学是"存储交给插件"——内核不提供存储能力，由专门的插件实现。存储层负责两件事：

1. **环境配置**：通过 `.env` 管理路径
2. **数据持久化**：定义目录结构和文件约定，供插件读写

---

## 环境变量（.env）

项目根目录下的 `.env` 文件存储路径配置。

### 核心变量

| 变量名       | 默认值       | 说明                     |
| --------- | --------- | ---------------------- |
| `CT_HOME` | `./ct`    | 项目数据根目录，所有运行时数据存储在此路径下 |

> `CT_HOME` 为**相对仓库根目录**（即 `.env` 所在目录）解析的路径。
> 下文为便于阅读出现的 `ct/` 均表示 `$CT_HOME`，实际使用时一律以 `$CT_HOME` 为准。


### .env 示例

```env
CT_HOME=./ct

```

---

## 目录结构

`$CT_HOME`（默认 `./ct`）是所有运行时数据的根目录。完整结构如下：

```
$CT_HOME/                               # 默认 ./ct
├── profile/                            # 环境配置目录
│   └── web/                            # web 环境（可扩展其他环境）
│       ├── package.json                # 环境级插件清单（ct.profile）
│       ├── cordis.patch.yml            # 环境级配置覆盖
│       └── commands.yml                # 环境级命令注册（profile 原生自带，由 CLI 管理）
├── node_modules/                       # 插件包存储（pnpm 管理）
├── package.json                        # 用户级依赖清单
└── cordis.patch.yml                    # 用户级配置覆盖
```

---

## 文件说明

### 配置文件

#### `cordis.patch.yml`（用户级）

`$CT_HOME/cordis.patch.yml`，存储用户级的 Cordis 配置。此文件的配置优先级高于环境级配置。

用户级 / 环境级使用 `id` + `config` 格式（**与插件级的 insert 声明格式天然不同**）：

```yaml
- id: host
  config:
    vmTimeoutMs: 10000
```

#### `profile/web/cordis.patch.yml`（环境级）

`$CT_HOME/profile/web/` 下的 `cordis.patch.yml`，存储当前环境（web）的 Cordis 配置。优先级低于用户级配置。

#### `profile/web/commands.yml`（环境级命令）

`profile` 原生自带的命令注册文件，**由 CLI 逻辑管理**（增删命令、供 CLI 层读取）。

### 插件管理文件

#### `package.json`（用户级）

`$CT_HOME/package.json`，记录用户通过 pnpm 安装的插件包。由 pnpm 自动维护。

#### `profile/web/package.json`（环境级）

`$CT_HOME/profile/web/` 下的 `package.json`，通过 `ct.profile` 声明**需要加载哪些插件**。
由启动层读取；**加载顺序不由它决定**，而由 `inject` 依赖关系决定（见[[项目文档/项目文档/cordis-tavern项目设计/启动层|启动层]]）。

```json
{
  "ct": {
    "profile": [
      "ct-plugin-host",
      "ct-plugin-client-web"
    ]
  }
}
```

#### `node_modules/`

由 pnpm 管理的插件包存储目录。

---

## 配置优先级

配置采用多层级覆盖机制，优先级从高到低：

```
CLI 参数 > 用户级配置 > 环境级配置 > 默认值
```


---

## 存储适配器（规划）

具体驱动实现（JSON 文件 / SQLite / IndexedDB）将作为独立插件提供，由配置中心决定加载哪个。
